# Bounded Firebase token refresh for protected webhook requests

The change replaces repository-relative Firebase credentials with Application Default Credentials, gives protected Webhook Intelligence routes stable authentication outcomes, and caps expired-token recovery at one refresh and one replay. The client preserves the initiating user, controls the bearer header, signs out after terminal authentication failures, and separates transport failures from authentication failures. Protected v1 routes remain tenant-scoped, while ingestion and trading safeguards are unchanged. **Watch for:** **confirmed** missing credentials take precedence over a missing bearer and incorrectly return `503` instead of `401 authentication_required`; **likely** competing Render manifests can deploy different API origins while Netlify targets only one.

## High-level view

Firebase Admin now initializes through ADC, logs only sanitized failure metadata, and passes the app explicitly to `verify_id_token(..., check_revoked=True)`. Verification fails closed with precise expired, invalid, revoked, disabled, missing-UID, and infrastructure outcomes, but **confirmed** app readiness is checked before bearer syntax, breaking the missing-token contract when both credentials and the header are absent.

The frontend captures the Firebase user object and UID and only force-refreshes after the first `401 token_expired`. It replaces caller-supplied authorization, permits at most two fetches, stops on user changes, reauthenticates after a replayed `401`, and does not retry or sign out for network errors, timeouts, or authentication-service `503` responses.

The root Render manifest and Netlify configuration use `https://vivek-raj.onrender.com`, while `backend/render.yaml` defines `https://vivek-crypto-trader-api.onrender.com`. **Likely** the active API and generated webhook origin will differ depending on which plausible deployment manifest an operator uses.

All `/api/v1/webhooks/*` management and reporting routes remain guarded and derive tenancy from verified `uid`/`sub`. Public ingestion retains endpoint-secret, IP, rate-limit, replay, idempotency, and risk controls; both live-execution flags default false and the unconfigured live adapter remains fail-closed.

## Missing bearer is masked by Firebase Admin availability

**High — blocker — confirmed.** `require_firebase_auth` returns `503 auth_service_unavailable` when `firebase_app` is `None` before parsing `Authorization` (`backend/webhook_intelligence.py:866-880`). A missing or empty bearer therefore cannot produce the required `401 authentication_required` during an ADC outage. Move syntactic bearer validation before app readiness, while retaining sanitized `503` for a present bearer that cannot be verified.

Backend tests cover missing headers with an available app and unavailable Admin with a bearer, but not their intersection (`backend/tests/test_firebase_auth.py`). This blocker must be fixed before completion.

## One-refresh request boundary

The non-recursive state machine calls `getIdToken(false)` and `getIdToken(true)` on the same captured user, with object-and-UID checks before refresh and replay. A second `401` invokes the single-flight reauthentication boundary and returns `reauthentication_required`; invalid, revoked, disabled, and refresh-failure paths do not replay. `Headers.set` ensures one service-controlled bearer per attempt, and replay preserves the webhook service’s URL, method, serialized body, query, and non-authentication headers.

Network failures remain status `0`; timer aborts are `request_timeout`; neither path retries or signs out. The 19 passing frontend tests cover exact token/fetch counts, hostile bearer replacement, POST replay fidelity, second-`401`, refresh failure, user switching, concurrent terminal failures, transport failures, and auth-service `503`.

## Conflicting Render origins

**Medium — likely.** `netlify.toml`, the frontend fallback, and root `render.yaml` use `https://vivek-raj.onrender.com`; the changed `backend/render.yaml` creates `vivek-crypto-trader-api` and sets `WEBHOOK_BASE_URL=https://vivek-crypto-trader-api.onrender.com`. The values contain no credentials and normalize correctly, but two plausible deployment sources now disagree on service identity. Consolidate the manifests or explicitly map and test which origin serves protected API calls and which generates callbacks.

## Verified authentication and trading boundaries

The v1 decorator maps expired, invalid, revoked/deleted-user, disabled-user, missing-UID, certificate-fetch, and unknown verification failures without returning token, claim, credential, path, or exception text. ADC setup does not load a repository credential file or inspect Firebase Admin private state; examples expose only non-secret variable names, paths, project IDs, and URLs.

Every protected v1 route remains decorated and tenant-scoped through `g.auth_uid`. The authentication diff does not weaken endpoint ownership, webhook-secret comparison, replay protection, idempotency, risk validation, rate limiting, or the execution-blocked live path.

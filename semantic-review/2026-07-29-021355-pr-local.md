# TradingView overlay lifecycle into the journal

The extension adds the intended manual path: `Sync Now` reads Entry, SL, Target, side, quantity, and symbol from the visible TradingView overlay, then PATCH-upserts an open record at `users/{uid}/trades/{tradeId}`; later overlay disappearance PATCHes that same ID as closed. The stable ID and direct Firestore subscription support immediate Dashboard visibility and idempotent updates. The change is not ready to ship because other new paths write into the same collection and several open/close semantics violate the no-fake-values and later-closure requirements. **Watch for:** **blocker, confirmed** non-overlay writers; **blocker, confirmed** nulls converted to fake zeroes; **high, confirmed** open trades included in completed metrics; **high, confirmed** one-hour auth expiry blocking closure; **high, confirmed** cross-tab state corruption; **high, confirmed** sampled/stale prices recorded as exits; **high, confirmed** no lifecycle tests.

## High-level view

The normal single-tab path preserves one identity: the content script creates a `tradeId` once, and the background worker uses Firestore PATCH against that ID for both open and closed states. Removing Firestore-side `createdAt` ordering also lets records with extension-authored ISO timestamps reach the Dashboard.

The collection is not overlay-only. CSV imports, internal Pro Trading closures, and Binance income/order-history polling all write into `users/{uid}/trades`, introducing exactly the alternate sources the requirement excludes (**blocker, confirmed**).

Optional numeric fields are normalized through `Number(null)`, which yields zero. Open trades therefore persist fake values such as `exitPrice: 0`, defeating the new Dashboard null handling (**blocker, confirmed**).

Dashboard statistics, equity data, Analytics, and Calendar treat every document as a completed outcome. The newly synced open record can alter win rate and P&L before it closes (**high, confirmed**).

The extension stores a pasted Firebase ID token that expires after one hour and has no refresh mechanism. A longer-running trade cannot update its open document on closure without manual reconnection (**high, confirmed**).

All TradingView tabs share one persisted `activeChartTrade`. A tab can restore another tab's position and close or replace the wrong document using a different chart context (**high, confirmed**).

After three missing scans, closure records the current chart quote or a cached quote as the execution price. Neither is an overlay-reported fill, so the stored exit and derived P&L can be inaccurate (**high, confirmed**).

No automated test exercises capture, upsert identity, duplicate Sync Now clicks, closure, failure recovery, or Dashboard treatment of open records (**high, confirmed**).

<summary>Issues (7)</summary>

1. **Competing journal writers** — **Blocker, confirmed:** CSV import, Pro Trading, and Binance history all write to `users/{uid}/trades`. Remove those additions or isolate them outside the journal collection and enforce overlay capture at the sole write boundary.
2. **Null-to-zero fabrication** — **Blocker, confirmed:** nullable fields are passed through `Number(...)`, turning unknown exits and other values into zero. Reject null/blank input before numeric parsing and serialize unavailable values as Firestore nulls.
3. **Open trades counted as outcomes** — **High, confirmed:** Dashboard and shared analytics include open records in completed-trade totals and P&L. Base performance calculations on a closed-trades projection and expose open positions separately.
4. **Non-refreshable closure authorization** — **High, confirmed:** the pasted Firebase token expires after one hour, after which closure PATCHes fail. Use a refreshable extension Firebase Auth session and refresh/retry once on 401.
5. **Cross-tab active-trade collision** — **High, confirmed:** every TradingView tab shares one active snapshot key. Store active state per tab and reject closure when chart identity does not match.
6. **Invented exit precision** — **High, confirmed:** a delayed or cached market quote is saved as the execution price after the overlay disappears. Leave exit and derived P&L null unless the overlay supplies an authoritative closing value.
7. **Untested trade lifecycle** — **High, confirmed:** there are no tests for the core capture/upsert/closure contract. Add deterministic extension and Dashboard tests before shipping.

## Competing writers defeat the overlay-only contract

**Blocker — confirmed.** `CSVImport` writes parsed history rows through `addTrade` (`src/components/CSVImport.jsx:59`), and the new UI exposes it from Dashboard and Trade History (`src/pages/Dashboard.jsx:96`, `src/pages/TradeHistory.jsx:134`). `useTradeBridge` writes internal Pro Trading closures through the same API (`src/trading/useTradeBridge.js:30`) and is mounted at `src/trading/ProTrading.jsx:50`. `BinanceSyncService` polls realized income and raw trade history into `users/{uid}/trades` (`backend/binance_sync.py:199`, `229`); public backend routes accept a caller-supplied `userId` and invoke that writer (`backend/app.py:705-759`).

Remove the CSV additions, Pro Trading bridge, and Binance history sync from this change. If retained for a separate product, write them to isolated collections, do not merge them into `TradeContext`, authenticate backend requests and derive UID from the verified principal, and enforce `captureSource === 'tradingview_chart_overlay'` at the only `users/{uid}/trades` write boundary.

## Null overlay values become fabricated zeroes

**Blocker — confirmed.** `processTradeData` uses `Number.isFinite(Number(record.field))` across nullable fields (`chrome-extension/background.js:177-208`). Because `Number(null)` and `Number('')` are `0`, an open snapshot's `exitPrice: null` is persisted as `exitPrice: 0`; missing P&L, leverage, margin, risk/reward, P&L percent, and fees have the same failure. Dashboard's `exitPrice == null` branch then cannot display `Open`.

Use one parser that returns null before coercion when a value is null, undefined, or blank, and apply it to every optional numeric field. Validate Entry, SL, Target, and quantity separately as required finite overlay values. Assert that an open Firestore payload retains literal null for unavailable exit and result fields.

## Open positions corrupt Dashboard performance

**High — confirmed.** `getStats` classifies every subscribed record by P&L and uses `trades.length` as the denominator (`src/context/TradeContext.jsx:160-188`). Dashboard also builds equity and invested capital from the full array (`src/pages/Dashboard.jsx:22-25`). An open overlay with unrealized P&L becomes a premature win/loss; even with null P&L, it inflates total trades and depresses win rate. Analytics and Calendar carry the same completed-record assumption.

Derive `closedTrades` from `status`/`positionStatus` and use it for outcomes, P&L, streaks, expectancy, equity, invested capital, and calendar aggregates. Keep `openTrades` separate, and render an explicit Open state without assigning a result.

## Token expiry breaks later closure

**High — confirmed.** Settings generates one Firebase ID token (`src/pages/Settings.jsx:324`) and states that it expires after one hour (`src/pages/Settings.jsx:338`). The popup stores only that token and UID (`chrome-extension/popup.js:187`), while the background worker rejects an expired JWT without refreshing it (`chrome-extension/background.js:46-54`). The local snapshot remains retryable, but Firestore stays open until the user manually generates and pastes another token.

Replace pasted bearer-token storage with a refreshable Firebase Auth session in the extension and obtain a current ID token before each write. On 401, refresh once and retry the same idempotent PATCH; do not require user intervention for a normal later closure.

## Cross-tab state can close the wrong trade

**High — confirmed.** `ACTIVE_STORAGE_KEY` is global (`chrome-extension/content.js:17`), and every matching TradingView tab loads and writes it (`chrome-extension/content.js:356`, `520`, `684-686`). Since connection state starts capture in every tab, a second tab can restore the first tab's synced snapshot and run replacement/closure against a different chart.

Register content scripts with the service worker, persist snapshots by `sender.tab.id`, route Sync Now to that tab's state, and clear state on `chrome.tabs.onRemoved`. Before closure or replacement, require the stored symbol, exchange, and timeframe to match the current chart.

## Overlay disappearance does not provide an execution price

**High — confirmed.** Closure waits for three misses (`chrome-extension/content.js:15`, `570`) and passes `detected.marketPrice ?? activeSnapshot.currentPrice` into completion (`chrome-extension/content.js:572`). Any finite value is labeled `chart_price_at_overlay_close` (`chrome-extension/content.js:386`), although the first value is sampled seconds after disappearance and the fallback predates closure. The background can then derive P&L from that non-fill price.

Update the same document with closed status and observation time, but leave `exitPrice`, `exitPriceSource`, and derived P&L null unless the overlay itself exposes a final execution price or realized P&L. Unknown is preferable to fabricated precision.

## Lifecycle behavior has no automated coverage

**High — confirmed.** No tracked or untracked test/spec files exist, and `package.json` has no test script. `npm run build` succeeds with bundle-size and mixed-import warnings, but compilation does not validate this stateful browser/Firestore behavior.

Add mocked Chrome, canvas, and Firestore tests proving the open PATCH path, stable identity across repeated Sync Now and closure, null preservation, rejection of non-overlay payloads, tab isolation, auth refresh/retry, and exclusion of open records from completed Dashboard metrics.
